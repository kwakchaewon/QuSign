# QuSign 서비스 테스트 시나리오

> 현재 구현된 기능 기반 수동 테스트용 시나리오 (2026-06-05 기준)
>
> 체크 방법: 통과 `[V]` / 실패 `[X]` / 미확인 `[ ]`

## 사전 준비

- 테스트 PDF 파일 1~3개 준비
- 브라우저 2개 (또는 시크릿 창) 열기
- 서비스 기동:
  ```bash
  docker compose up -d          # MinIO + Redis
  ./gradlew bootRun             # 백엔드 (local 프로파일)
  cd frontend && npm run dev    # 프론트엔드
  ```
- 테스트 계정 2개 필요
  - **A (요청자):** `requester@test.com` / `Test1234!`
  - **B (서명자):** `signer@test.com` / `Test1234!`

## 시나리오 1 — 기본 서명 플로우

**목적:** 핵심 플로우 전체 확인

- [V] **1** [A] `/signup` → `requester@test.com` / `Test1234!` 가입 → 로그인 페이지 이동 확인

- [V] **3** [A] 로그인 → `/home` 진입 → 대시보드 통계 카드 모두 0 표시
- [V] **4** [A] `서명 요청` → PDF 업로드 → 서명자 이메일 `signer@test.com` 입력 → 요청 생성 → 완료 화면에서 서명 링크 표시
- [V] **5** [A] 헤더 벨 아이콘 → 배지 없음 확인 (아직 서명 전)
- [V] **6** [B] 로그인 → 헤더 벨 아이콘 → 🔔 미읽음 1 "서명 요청" 알림 확인
- [V] **7** [B] 알림 클릭 → `/sign/{token}` 서명자 화면 진입 (미로그인 시 로그인 후 자동 이동)
- [V] **8** [B] 문서 정보(요청자·만료일·SHA3-256) 확인 → PDF 미리보기 스크롤 → 동의 체크박스 2개 체크 → 계정 비밀번호 입력 → 서명하기 → "서명 완료" 화면
- [V] **9** [A] 헤더 벨 아이콘 → 🔔 미읽음 1 "서명 완료" 알림 확인
- [V] **10** [A] 알림 클릭 → 문서 상세 페이지 → 서명자 상태 `SIGNED` + 서명 일시 표시
- [V] **11** [A] 서명된 PDF 다운로드 → `파일명_qusigned.pdf` 다운로드 확인
- [V] **12** [A] `/verify` → 토큰 입력 → ✅ 유효한 서명 + 서명자 이메일 표시

## 시나리오 2 — 번들 서명 (다중 문서)

**목적:** 여러 PDF를 번들로 묶어 한 번의 서명으로 전체 처리

- [V] **1** [A] 로그인 → `서명 요청` 진입
- [V] **2** PDF 3개 드래그앤드롭 업로드 → 파일 목록 3행 표시, 각 파일 해시값 계산 확인
- [ ] **3** 서명자 이메일 pill 방식으로 입력 (`signer@test.com` + Enter) → pill 표시
- [ ] **4** 요청 생성 → 완료 화면에서 **"파일명.pdf 외 2건"** 번들 표시 + 서명자별 링크 **1개** 생성 확인 (문서별 3개 아님)
- [ ] **5** [A] 대시보드(`/documents`) 진입 → 목록에 **"파일명.pdf 외 2건"** + 숫자 뱃지 `3` 표시, 개별 문서 행 미표시 확인
- [ ] **6** [A] 번들 행 클릭 → `/bundles/{id}` 번들 상세 페이지 진입 → 3개 문서 파일명 목록 확인
- [ ] **7** [B] 로그인 → 알림 확인 → **알림 1개** ("파일명.pdf 외 2건 서명 요청")
- [ ] **8** [B] 알림 클릭 → `/sign/{bundle_token}` 서명자 화면 진입 → 문서명 **"파일명.pdf 외 2건"** + 파일 목록 3개 표시 확인
- [ ] **9** [B] 동의 체크박스 2개 체크 → 비밀번호 입력 → 서명하기 → 3개 문서 **전부** 서명 처리됨
- [ ] **10** [B] 서명 완료 화면에서 문서별 다운로드 버튼 3개 확인 → 각각 클릭 시 `파일명_qusigned.pdf` 개별 다운로드
- [ ] **11** [A] 번들 상세 페이지 새로고침 → 서명자 상태 `SIGNED` + 서명 일시 표시 + 문서별 다운로드 버튼 3개 확인
- [ ] **12** PDF 5개 초과 업로드 시도 → 클라이언트 차단 메시지 표시

- [ ] **1** [A] 서명 요청 생성 (서명자: `signer@test.com`)
- [ ] **2** [A] 문서 상세 페이지 → 서명자 행의 "취소" 버튼 클릭 → 확인 모달 표시
- [ ] **3** 모달 확인 → 서명자 상태 `CANCELLED`로 변경 확인
- [ ] **4** [B] 알림 확인 → ❌ "서명 요청 취소" 알림
- [ ] **5** [B] 서명 링크 직접 접속 → "취소된 요청" 안내 화면
- [ ] **6** [A] CANCELLED 상태 서명자 행 → 취소 버튼 미표시 확인

## 시나리오 5 — 계정 설정

**목적:** 비밀번호 변경, 알림 설정, 탈퇴

- [ ] **1** [A] 로그인 → `/settings` → 비밀번호 변경 / 알림 / 탈퇴 섹션 표시
- [ ] **2** 비밀번호 변경: 현재 `Test1234!` → 새 `NewPass456!` → 성공 토스트
- [ ] **3** 로그아웃 후 기존 비밀번호로 로그인 시도 → 로그인 실패
- [ ] **4** 새 비밀번호로 로그인 → 성공
- [ ] **5** 알림 설정에서 "서명 완료 알림" OFF → 저장 성공
- [ ] **6** 다른 계정이 서명 완료 후 [A] 알림 확인 → 알림 미생성
- [ ] **7** 계정 탈퇴: 이메일 입력 확인 → 탈퇴 → 로그인 화면으로 이동
- [ ] **8** 탈퇴한 이메일로 로그인 시도 → "탈퇴한 계정" 오류

## 시나리오 6 — 엣지 케이스

- [ ] **중복 서명 요청** — 동일 문서 + 동일 서명자로 PENDING 중 재요청 → 409 "이미 요청 중" 오류
- [ ] **잘못된 비밀번호로 서명** — 서명 실행 시 틀린 비밀번호 입력 → 400 "비밀번호 오류"
- [ ] **타인 문서 다운로드** — [B]가 [A]의 문서 ID로 다운로드 시도 → 403/404
- [ ] **50MB 초과 PDF 업로드** — 대용량 파일 업로드 시도 → 클라이언트 사전 차단
- [ ] **PDF 아닌 파일 업로드** — `.jpg` 파일 업로드 시도 → 파일 형식 오류
- [ ] **비밀번호 규칙 위반 가입** — `1234` 입력 → 실시간 규칙 피드백 + 차단

## 알림 실시간성 확인

A/B 두 창을 나란히 열고:

- [ ] [A]가 서명 요청 생성 → [B] 화면에서 벨 아이콘 배지가 **즉시(< 1초)** 증가
- [ ] [B]가 서명 실행 → [A] 화면에서 벨 아이콘 배지가 **즉시** 증가

페이지 새로고침 없이 실시간으로 반응하면 SSE 정상 동작 확인 완료.
